# 当前浏览器能力下 Steward 能做到什么程度

基于 Chrome MV3 与现有权限，本文梳理：**已具备的能力**、**边界与限制**、**可拓展方向**。

---

## 一、已具备的能力（当前权限与 API）

### 1. 已有权限（manifest）

- `storage`：sync/local 配置与工作流
- `activeTab` / `tabs`：当前/全部标签，切换、关闭、移动、固定、静音
- `clipboardWrite`：复制到剪贴板
- `history`：浏览历史
- `bookmarks`：书签
- `management`：扩展的启用/禁用/卸载、列表
- `downloads`：下载列表、打开/暂停/继续/取消
- `topSites`：常用网站
- `host_permissions: <all_urls>`：任意 URL 的 fetch、content script 注入

### 2. 已实现的功能边界

| 能力 | 实现方式 | 边界 |
|------|----------|------|
| 命令框 | popup + content 注入 iframe | 弹窗/页面内均可打开，快捷键可配置 |
| 历史/书签 | chrome.history / chrome.bookmarks | 受 API 限制（条数、排序），无全文搜索 |
| 标签页 | chrome.tabs | 切换、关、移、固定、静音；无跨窗口拖拽等 |
| 扩展管理 | chrome.management | 启用/禁用/卸载、打开选项页 |
| 下载 | chrome.downloads | 列表、打开所在文件夹、暂停/继续/取消 |
| 常用网站 | chrome.topSites | 仅 Chrome 提供的列表 |
| 自定义命令（方案 A） | 配置 + fetch + JSON 解析 | 触发词 + 静态/URL 数据源 + 打开 URL/复制/工作流，**不执行用户代码** |
| 工作流 | 内置命令组合（his/bm/tab/...） | 顺序执行、选择序号，无分支/循环 |
| URL 拦截/替换 | content + 配置 | 按 URL 屏蔽或替换为指定页 |
| 外观 | 主题/字号/强调色/圆角等 | 仅限命令框 UI，不改系统或网页 |

## 二、浏览器与审核的硬限制

### 2.1 不能做的事（MV3 + 商店政策）

- **在扩展内执行用户提供的代码**：禁止 `eval`、`new Function()`、远程拉脚本再执行；无法恢复旧版「写 JS 插件在扩展里跑」。
- **任意注入脚本到页面**：content script 是声明式注入，不能根据用户输入动态 `eval` 或加载未审核脚本。
- **突破 CSP**：扩展自己的页面也受 CSP 约束，不能通过「用户脚本」绕过。

### 2.2 能力上限（Chrome API 本身）

- **历史/书签**：无全文检索 API，只能按时间/URL 等过滤，搜索依赖扩展侧已拉取的数据。
- **系统级**：无法直接调系统应用、无法读本地文件（除 Native Messaging 约定路径）、无法后台常驻（SW 可被回收）。
- **网络**：可 fetch 任意 URL（需 host_permissions），但受 CORS；无法直接发 TCP/WebSocket 到任意地址（需扩展或页面上下文）。
- **剪贴板**：当前仅写；读剪贴板需用户手势或 optional permission（如 `clipboardRead`）。

## 三、在现有边界内还能做到什么程度

### 3.1 不增加权限、不执行用户代码

- **自定义命令增强**
  - 更多数据源：如「当前窗口所有标签」「最近 N 条历史」「书签文件夹」等，用现有 API 在 background 实现，配置里选类型/参数即可。
  - 更多动作：如「在新标签打开并置顶」「复制为 Markdown 链接」等，仍是固定逻辑 + 占位符。
- **工作流增强**
  - 更多内置步骤类型（如「等待 500ms」「聚焦到某窗口」等），仍为预定义步骤，非用户脚本。
- **体验与数据**
  - 历史/书签结果缓存、防抖、分页，提升大数量时的流畅度。
  - 自定义命令支持缓存 URL 结果（带 TTL）、简单去重。
- **界面**
  - 命令框内更多快捷键（如 Ctrl+数字选结果）、主题/布局可调项增多、无障碍改进。

### 3.2 可选权限（用户同意后再用）

- **`clipboardRead`**：读剪贴板，实现「粘贴并搜索」「从剪贴板取 URL 再打开」等。
- **`notifications`**：工作流结束或某命令执行后发系统通知。
- **`alarms`**：定时/周期任务（如「每 N 分钟同步一次自定义命令的 URL 缓存」），在 SW 里用 chrome.alarms 实现。

### 3.3 不增加权限但用更多已有 API

- **`chrome.windows`**：已有 tabs 就间接有 windows；可做「窗口列表」命令、将标签移到指定窗口等。
- **`chrome.sessions`（需权限）**：若申请 sessions，可做「最近关闭的标签/窗口」恢复。
- **`chrome.search`**：若申请 search，可用默认搜索引擎做「在地址栏搜索」式行为（与当前自定义搜索可并存）。

### 3.4 方案 B：Native Messaging（真脚本，需装本地程序）

- 用户在本机安装「Steward 脚本宿主」，扩展通过 Native Messaging 与宿主通信。
- 脚本在**系统进程**里跑（Node/Python/Bash 等），扩展只收发电报（如 JSON 行），不执行任何用户代码，符合 MV3。
- 能力接近 Alfred 的 Run Script：读本地文件、调系统命令、任意网络请求等；代价是安装与维护宿主、跨平台与升级成本。

## 四、总结对照

| 维度 | 当前能做到 | 硬限制 | 可拓展（不执行用户代码） |
|------|------------|--------|---------------------------|
| 数据源 | 历史/书签/标签/下载/常用站/自定义 URL（JSON） | 无全文检索 API、无本地文件 | 更多内置数据源类型、URL 缓存、可选 clipboardRead/sessions |
| 执行动作 | 打开 URL、复制、运行工作流、标签/扩展/下载操作 | 无 eval、无用户脚本 | 更多固定动作、可选 notifications |
| 自动化 | 工作流（顺序步骤 + 选择） | 无分支/循环、无定时 | 更多步骤类型、可选 alarms、方案 B 本地脚本 |
| 界面 | 命令框 + 选项页 + 外观配置 | 受 popup/content 与 CSP 约束 | 更多快捷键、主题与无障碍 |

**一句话**：在「不执行用户代码」的前提下，扩展还能在**更多数据源、更多固定动作、工作流步骤、缓存与体验、可选权限与 Native Messaging** 上继续延伸；真正「任意逻辑」只能通过方案 B 在本地脚本里实现。
